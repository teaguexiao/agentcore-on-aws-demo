# Runtime 模块迭代需求文档

> 版本: v1.0
> 日期: 2025-01-14
> 状态: 需求确认完成

## 1. 背景

当前 Runtime 模块（Direct Code Deployment 部分）有多个步骤是 Mock 实现，只是模拟输出预设的日志行，实际上没有真正执行任何命令。

### 1.1 当前状态

| 步骤 | 当前状态 | 说明 |
|------|---------|------|
| Part 1 | 静态文本 | 前置要求检查清单 |
| Part 2 | **Mock** | 初始化项目依赖 (uv init, uv add) |
| Part 3 | **Mock** | 创建 Agent 代码 (main.py) |
| Part 4 | 静态文本 | 本地测试指南 |
| Part 5-1 | **Mock** | 创建部署包 (zip) |
| Part 5-2 | 真实API | 上传S3 + 创建Runtime |
| Part 6 | 真实API | 查询 Runtime 状态 |
| Part 7 | 真实API | 调用 Agent |
| Part 8 | 真实API | 清理 Runtime + S3 |

### 1.2 问题

- Mock 步骤无法让用户体验真实的命令执行过程
- 用户无法自定义命令或代码
- 无法看到真实的文件变化

## 2. 目标

将 Runtime 模块 Direct Code Deployment 部分的 Mock 步骤改造为真实后端执行，实现：

1. **真实命令执行**: 所有命令在服务器后端真实执行
2. **用户可编辑**: 用户可以在前端修改每一步的命令或脚本
3. **实时输出**: 通过 SSE 流式返回 stdout/stderr
4. **文件可视化**: 每步执行后显示工作目录文件变化

## 3. 功能需求

### 3.1 工作目录管理

#### 3.1.1 初始化工作目录

- **触发**: 用户点击"初始化工作环境"按钮
- **行为**:
  - 生成唯一的 workspace_id
  - 在 `/tmp/agentcore_workspaces/{workspace_id}` 创建目录
  - 关联到当前登录用户的 session_id
- **约束**: 每个用户同时只能有一个工作目录
- **输出**: 显示 workspace_id 和完整路径

#### 3.1.2 清理工作目录

- **触发**: 用户点击"清理工作环境"按钮
- **前置条件**: 当前用户没有已部署的 Runtime 环境
- **行为**: 删除工作目录及所有内容
- **输出**: 清理成功/失败提示

#### 3.1.3 工作目录状态

- **显示**: 工作目录是否已初始化、workspace_id、路径
- **持久化**: 页面刷新后能恢复状态（基于登录用户的 session_id）

### 3.2 命令执行

#### 3.2.1 执行方式

- **环境**: 在服务器本地执行，工作目录为隔离的临时目录
- **输出**: 通过 SSE 流式返回 stdout/stderr
- **心跳**: SSE 连接需要心跳机制防止超时断开
- **超时**: 不设置命令执行超时

#### 3.2.2 用户可编辑

- 用户可以完全自由编辑 shell 命令
- 前端提供默认命令模板
- 安全提示: 显示警告说明命令将在服务器执行

### 3.3 文件写入

#### 3.3.1 代码文件创建

- **触发**: Part 3 创建 Agent 代码步骤
- **输入**:
  - 文件路径（相对于工作目录）
  - 文件内容（代码）
- **行为**: 后端写入文件到指定路径
- **输出**: 写入成功/失败

### 3.4 文件展示

#### 3.4.1 展示时机

- 每步执行完成后自动刷新显示

#### 3.4.2 展示内容

- 当前工作目录路径
- 文件树结构（递归显示子目录）
- 文件大小
- 区分文件和目录图标

#### 3.4.3 展示位置

- 在每个步骤卡片的输出区域下方显示（方案 C）

### 3.5 登录验证

#### 3.5.1 当前问题

Runtime 模块所有 API 端点缺少登录验证，任何人知道 API 路径可直接调用。

#### 3.5.2 要求

- 所有 Runtime API 端点必须添加 `Depends(get_current_user)` 验证
- 未登录用户调用 API 返回 401 错误

### 3.6 步骤流程

改造后的步骤流程：

| 步骤 | 类型 | 用户输入 | 执行方式 |
|------|------|---------|---------|
| Part 0 | 新增 | 无 | 初始化工作目录 |
| Part 1 | 保持 | 无 | 静态文本（前置要求检查） |
| Part 2 | 改造 | 可编辑命令 | SSE 流式执行 |
| Part 3 | 改造 | 可编辑代码 + 文件路径 | 后端写入文件 |
| Part 4 | 保持 | 无 | 静态文本（本地测试指南） |
| Part 5-1 | 改造 | 可编辑命令 | SSE 流式执行 |
| Part 5-2 | 保持 | 无 | 真实 API（上传S3 + 创建Runtime） |
| Part 6 | 保持 | Runtime ID | 真实 API（查询状态） |
| Part 7 | 保持 | Runtime ARN + Prompt | 真实 API（调用Agent） |
| Part 8 | 保持 | Runtime ID | 真实 API（清理Runtime） |
| Part 清理 | 新增 | 无 | 清理工作目录 |

## 4. 非功能需求

### 4.1 安全性

- **风险等级**: 高（允许执行任意 shell 命令）
- **使用场景**: 内部演示/个人使用
- **安全措施**:
  - 必须登录才能使用
  - 工作目录隔离在 `/tmp/agentcore_workspaces/`
  - 前端显示安全警告提示

### 4.2 性能

- SSE 心跳间隔: 15 秒
- 文件树最大深度: 5 层
- 文件树最大文件数: 100 个

### 4.3 可靠性

- 服务重启后工作目录信息丢失（可接受，因为在 /tmp）
- SSE 断开后需要前端能重连

## 5. 用户识别

- 基于登录系统的 session_id（cookie）
- 每个登录用户有独立的工作目录配额（1个）
- 不同用户的工作目录完全隔离

## 6. 约束条件

- 工作目录位置: `/tmp/agentcore_workspaces/{workspace_id}`
- 每用户最多 1 个工作目录
- 清理工作目录前必须先清理 Runtime
- 不支持文件下载（本期）
- 不支持在线编辑已有文件（本期）

## 7. 验收标准

1. ✅ 用户可以初始化工作目录
2. ✅ 用户可以在 Part 2 编辑并执行命令，看到实时输出
3. ✅ 用户可以在 Part 3 编辑代码并写入文件
4. ✅ 用户可以在 Part 5-1 编辑并执行打包命令
5. ✅ 每步执行后显示工作目录文件树
6. ✅ 用户可以清理工作目录
7. ✅ 所有 API 端点需要登录验证
8. ✅ SSE 连接稳定（心跳机制）
