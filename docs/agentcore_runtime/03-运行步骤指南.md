### Part 6: 检查 Runtime 状态 (真实 API)

**UI 操作**:
1. Runtime ID 已自动填充
2. 点击"检查状态"按钮
3. 查看状态结果

**后端行为**:
- 调用 `get_agent_runtime` API
- 返回当前状态

**可能的状态**:
- 🟡 `CREATING` - 创建中 (等待几分钟)
- 🟢 `READY` - 就绪,可以调用
- 🔴 `CREATE_FAILED` - 创建失败
- 🟡 `UPDATING` - 更新中
- 🔴 `UPDATE_FAILED` - 更新失败
- ⚫ `DELETING` - 删除中

**重要**: 只有状态为 `READY` 时才能调用!

---

### Part 7: 调用 Agent (真实 API)

**UI 操作**:
1. Runtime ARN 已自动填充
2. Session ID 已预填 (可修改,需 ≥33 个字符)
3. 输入 Prompt
4. 点击"调用 Agent"
5. 查看响应

**后端行为**:
- 调用 `invoke_agent_runtime` API
- 返回 Agent 响应

**请求示例**:
```json
{
  "runtime_arn": "arn:aws:bedrock-agentcore:...",
  "runtime_session_id": "dfmeoagmreaklgmrkleafremoigrmtesogmtrskhmtkrlshmt",
  "prompt": "Explain machine learning"
}
```

**响应示例**:
```json
{
  "status": "success",
  "response": {
    "result": "Machine learning is a subset of AI..."
  },
  "execution_time": "1.23s"
}
```

---

### Part 8: 清理 Runtime (真实 API)

**UI 操作**:
1. Runtime ID 已自动填充
2. 点击"删除 Runtime"
3. 确认删除警告
4. 等待删除完成

**后端行为**:
1. 调用 `delete_agent_runtime` API
2. 删除 S3 中的 deployment_package.zip
3. 清除会话数据

**注意事项**:
- ⚠️ 删除操作不可逆
- ✅ 会自动清除 S3 文件
- ✅ 会清除前端保存的状态

## Container Deployment 步骤

### 前置准备

**额外要求** (除了 Direct Code 的要求外):
- ✅ Docker 和 Docker Buildx 已安装
- ✅ ECR 仓库已创建
- ✅ Docker 镜像已构建并推送到 ECR
- ✅ 镜像架构为 `linux/arm64`
- ✅ 环境变量已配置:
  - `CONTAINER_ECR_REPOSITORY_NAME`
  - `CONTAINER_IMAGE_TAG`
  - `CONTAINER_EXECUTION_ROLE_ARN`

**镜像验证**:
```bash
# 检查镜像是否存在
aws ecr describe-images \
  --repository-name my-strands-agent \
  --region us-west-2

# 验证架构
docker manifest inspect \
  {account_id}.dkr.ecr.us-west-2.amazonaws.com/my-strands-agent:latest \
  | grep architecture
```

## 常见问题

### Q1: 部署包不存在怎么办?

**错误**: `部署包不存在: deployment_packages/...`

**解决**:
```bash
# 确认文件是否存在
ls -lh deployment_packages/strands_agent/deployment_package.zip

# 如果不存在,需要手动创建(参考 agentcore_runtime.md)
```

---

### Q2: Runtime 状态一直是 CREATING

**原因**: 首次创建需要初始化环境,正常需要 2-5 分钟

**解决**:
1. 等待几分钟
2. 定期点击"检查状态"刷新
3. 如果超过 10 分钟仍未 READY,检查:
   - CloudWatch Logs
   - IAM 角色权限
   - 部署包或镜像是否正确

---

### Q3: 调用失败 - Runtime 未就绪

**错误**: `Runtime status is not READY`

**解决**: 等待状态变为 `READY` 后再调用

---

### Q4: S3 权限错误

**错误**: `AccessDenied` 或 `403 Forbidden`

**解决**:
1. 确认 S3 Bucket 已创建
2. 检查 IAM 权限是否包含 `s3:PutObject` 和 `s3:GetObject`
3. 确认 Bucket 策略允许访问

---

### Q5: Container 镜像不存在

**错误**: `ImageNotFoundException`

**解决**:
1. 运行前置检查脚本
2. 确认已完成 Docker 构建和推送
3. 验证环境变量中的镜像 URI 正确

---

### Q6: Session ID 长度不足

**错误**: `Runtime Session ID 长度必须至少 33 个字符`

**解决**: 使用默认预填的 Session ID,或确保自定义 ID ≥33 字符

## 最佳实践

### 1. 测试流程
```
Step 1: 运行前置检查
Step 2: 先测试 Direct Code (更快)
Step 3: 确认流程后再测试 Container
Step 4: 测试完成后及时清理资源
```

### 2. 开发迭代
```
本地开发 → 本地测试 → 打包/构建 → 部署测试 → 验证 → 清理
```

### 3. 成本控制
- ✅ Runtime 本身不产生费用
- ✅ 只在调用时计费
- ⚠️ 但已部署的 Runtime 会占用资源配额
- ✅ 测试后及时删除
